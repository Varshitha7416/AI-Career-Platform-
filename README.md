# CareerNest (AI Career Platform)

A career platform for job seekers: job discovery (search, filters, save), application and interview tracking, AI resume analysis, AI cover letters, skill gap analysis with learning roadmaps, career programs, and a referral marketplace.

- **Server:** Express 5 + Mongoose 9 (CommonJS), in `server/`
- **Client:** React 19 + Vite + Tailwind v4, in `client/`
- **Database:** MongoDB (MongoDB Atlas in production)
- **AI:** Google Gemini is the primary provider. Groq (free tier) is an optional, off-by-default backup. See `docs/32-dual-ai-provider.md`.
- **Docs:** `docs/` holds numbered build notes and contracts. `CLAUDE.md` is a developer overview.

## Run locally

Two independent npm projects; run `npm install` in each.

```
cd server && cp .env.example .env     # then fill in the values (see below)
npm install && npm run dev            # API on http://localhost:5000

cd client && npm install && npm run dev   # app on http://localhost:5173
```

Required in `server/.env`: `MONGO_URI`, `JWT_SECRET` (at least 32 random characters), and `GEMINI_API_KEY` (AI features return 503 without it). Everything else is optional; `server/.env.example` documents each variable. Never commit `.env`.

Optional client setting: `VITE_API_URL` (default `http://localhost:5000/api`). It is read at **build time**.

## Tests

- `cd server && npm test` runs the mocked unit tests (no database, no network).
- Database-backed suites (`npm run test:auth`, `test:verify`, `test:contact`, `test:tracker`, `test:reset`, `test:account`, `test:profile`, `test:admin`, `test:settings`, `test:programs`, `test:resume-history`, `test:referrals`, `test:indexes`, `test:skillgap`, `test:roadmap`) need a **throwaway local MongoDB** and the matching `*_TEST_MONGO=mongodb://127.0.0.1:<port>` variable. They refuse any non-local database. Run them one at a time.
- `cd client && npm test`, `npm run lint`, `npm run build`.

## Deployment checklist

1. **Server environment:** set `NODE_ENV=production`, `MONGO_URI` (include the database name), a **new** `JWT_SECRET` of 32+ random characters (the server refuses to start in production with a weaker one), `GEMINI_API_KEY`, and `CLIENT_ORIGIN` (the exact URL of the deployed client; the default only allows `http://localhost:5173`).
2. **Behind a proxy or platform load balancer:** set `TRUST_PROXY=1` (number of proxy hops). Without it the login and signup rate limits see every user as the same address.
3. **Client build:** set `VITE_API_URL` (ending in `/api`) before `npm run build`. The host must serve `index.html` for unknown paths (single-page app rewrite), or direct links such as `/privacy` will 404.
4. **Database indexes:** automatic index creation is off for Atlas. Take an Atlas backup, then run `npm run indexes` (dry run), review it, and apply with `MAINTENANCE_ALLOW_REMOTE_DB=<db name> npm run indexes -- --apply --confirm-backup`. This creates the unique indexes the app relies on.
5. **First admin:** `npm run bootstrap:admin` (see `docs/23`). It needs a verified account.
6. **Email:** no real email provider is configured yet (see `docs/22`). Until one is, "Forgot password" and verification emails cannot be delivered; email verification is optional, so the rest of the app is unaffected.
7. **AI backup provider:** leave `AI_FALLBACK_PROVIDER=none` and `GROQ_PRIVACY_ACK=false` unless you have followed the activation steps in `docs/32`.

## Safety notes

- `npm run seed` deletes all companies and jobs and is guarded against remote databases and production. The other seed and maintenance scripts are dry-run by default and are documented in `CLAUDE.md`.
- Job listings generated by the demo seed are labelled "Demo" in the UI and are not real vacancies.
